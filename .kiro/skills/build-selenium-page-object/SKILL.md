# Build a resilient Selenium page object

Produces one page object (or page component) for a Vue 3 screen in KEYinfinity, built so that a platform regeneration of the markup does not turn the suite red.

Output is a **markdown snippet with its intended file path** under `src/QAAutomation.UI/Pages` or `src/QAAutomation.UI/Components`. Do not write `.cs` files from this skill unless the user explicitly asks for files.

Locator contract, wait helper, driver lifecycle and failure-artefact rules: #[[file:ui-automation-selenium.md]]. What a step may call: #[[file:step-definitions.md]]. Layout and naming: #[[file:project-structure.md]]. Pinned `Selenium.WebDriver` / `Selenium.Support` versions: #[[file:tech-stack.md]]. Readability rules: #[[file:code-style.md]]. Screen and domain vocabulary: #[[file:domain-keyinfinity.md]].

Four standing rules:

1. **Part of KEYinfinity's UI is generated by a model-driven platform.** Anything the generator owns — auto `id`, hashed `class`, DOM position, Vue scoped-style attributes — is not a locator. It can change on a platform upgrade that changed no behaviour.
2. **Selenium does not wait.** Every touch of a dynamic element goes through the shared `ElementWaits` helper. A bare `FindElement` on something the app renders asynchronously is a defect waiting to happen.
3. **No assertions inside a page object.** It waits, then returns a value or an element; the step asserts.
4. **Page objects are synchronous.** Selenium's C# API is synchronous — no `async`, no `Task`, no `*Async` suffix in UI code.

## Step 1 — Inventory the screen

Before writing code, list what the suite actually needs to touch. Anything not on the list does not get a locator.

| Record | Example |
| --- | --- |
| Screen name and capability | VAT return detail, `@vat` |
| Interactive elements the suite uses | finalise button, submit button, period selector |
| Values the suite reads | status badge, box totals, reconciled balance |
| Collections | VAT box lines, statement line rows |
| Navigations out | finalise → submission confirmation screen |
| **Which elements are rendered asynchronously** | the grid, the status badge, anything behind a spinner — these decide where the waits go |
| Generated vs hand-written | which regions come from the model-driven platform **(ASSUMPTION until confirmed with the platform owners)** |

A page object with twenty locators for a screen the suite uses three elements of is maintenance debt. Keep the inventory honest.

## Step 2 — Agree the `data-testid` values

`data-testid` is a contract with the Vue 3 and platform teams, not a request. Produce the list of ids the screen needs so the front-end change can be raised in the same pull request.

| Rule | Detail |
| --- | --- |
| Shape | kebab-case, business-shaped, `<area>-<thing>-<action>`: `vat-return-finalise`, `bankrec-statement-import` |
| Stability | never generator output, never index-based, never a translated label |
| Generated screens | the id must be emitted by the **model/template**, so every generated instance gets one |
| Collections | a repeated id on the row, plus a nested id per cell, so rows are found by business content, not position |
| Change control | renaming or removing an id is a breaking change, reviewed and updated in the same PR |

**With Selenium this step is load-bearing, not advisory.** Selenium has no `GetByRole` or `GetByLabel`, so there is no accessibility-based fallback to drop to. If the platform cannot emit ids from the template layer, escalate it as a blocker and renegotiate the locator priority with the owners. Do not quietly write XPath.

## Step 3 — Choose locators in priority order

| Priority | Strategy | Use when |
| --- | --- | --- |
| 1 | `By.CssSelector("[data-testid='...']")` via the `TestIdLocator` helper | default for every element the suite touches |
| 2 | A stable, meaningful attribute, or an accessible/semantic selector — `By.Name`, `By.CssSelector("button[aria-label='...']")` | no test id yet and the element carries something genuinely stable |
| 3 | `By.XPath` or a structural CSS selector | last resort, with a justification comment and a linked work item to replace it |

```csharp
// Priority 1 — contract test id, through the one helper that owns the attribute name.
private static readonly By FinaliseButton = TestIdLocator.ByTestId(FinaliseTestId);

// Priority 2 — stable attribute, acceptable while the test id is being added.
private static readonly By PeriodStartField = By.Name("periodStart");

// Priority 3 — structural. Needs a justification and a ticket.
// Justification: the generated grid emits no test id on the total row yet. KEYINF-1234.
private static readonly By GeneratedGridTotalRow = By.CssSelector("[data-generated-grid] tfoot tr");
```

Note the shape: **`private static readonly By`**, never a cached `IWebElement`. A `By` cannot go stale; an element can, and will, the moment Vue re-renders.

For rows, match on the business value rather than an index. Position is the first thing a regeneration changes, and this is a `foreach`, not LINQ:

```csharp
private IWebElement FindStatementLineRow(string transactionReference)
{
    // Wait for at least one row before iterating, or the collection comes back empty.
    this.waits.WaitUntilVisible(StatementLineRow);

    IReadOnlyCollection<IWebElement> rows = this.driver.FindElements(StatementLineRow);

    foreach (IWebElement row in rows)
    {
        if (row.Text.Contains(transactionReference))
        {
            return row;
        }
    }

    throw new NoSuchElementException(
        "No statement line row contains transaction reference " + transactionReference + ".");
}
```

## Step 4 — Shape the class

```csharp
// src/QAAutomation.UI/Pages/BankReconciliationPage.cs
using OpenQA.Selenium;
using QAAutomation.Core.Utilities;

namespace QAAutomation.UI.Pages;

public sealed class BankReconciliationPage
{
    private const string ImportStatementTestId = "bankrec-statement-import";
    private const string StatementFileInputTestId = "bankrec-statement-file";
    private const string MatchLineTestId = "bankrec-line-match";
    private const string StatementLineRowTestId = "bankrec-statement-line-row";
    private const string ReconciledBalanceTestId = "bankrec-reconciled-balance";
    private const string ImportSpinnerTestId = "bankrec-import-progress";

    private static readonly By ImportStatementButton = TestIdLocator.ByTestId(ImportStatementTestId);
    private static readonly By StatementFileInput = TestIdLocator.ByTestId(StatementFileInputTestId);
    private static readonly By StatementLineRow = TestIdLocator.ByTestId(StatementLineRowTestId);
    private static readonly By ReconciledBalanceValue = TestIdLocator.ByTestId(ReconciledBalanceTestId);
    private static readonly By ImportSpinner = TestIdLocator.ByTestId(ImportSpinnerTestId);
    private static readonly By MatchLineButton = TestIdLocator.ByTestId(MatchLineTestId);

    private readonly IWebDriver driver;
    private readonly ElementWaits waits;

    public BankReconciliationPage(IWebDriver driver, ElementWaits waits)
    {
        this.driver = driver;
        this.waits = waits;
    }

    public void ImportStatement(string statementFilePath)
    {
        IWebElement importButton = this.waits.WaitUntilClickable(ImportStatementButton);
        importButton.Click();

        IWebElement fileInput = this.waits.WaitUntilVisible(StatementFileInput);
        fileInput.SendKeys(statementFilePath);

        // The import panel shows a progress indicator; waiting for it to clear is the
        // screen's own readiness signal, not an arbitrary delay.
        this.waits.WaitUntilGone(ImportSpinner);
    }

    public MatchConfirmationPage MatchLine(string transactionReference)
    {
        IWebElement row = FindStatementLineRow(transactionReference);
        IWebElement matchButton = row.FindElement(MatchLineButton);
        matchButton.Click();

        return new MatchConfirmationPage(this.driver, this.waits);
    }

    public string ReadReconciledBalance()
    {
        IWebElement balance = this.waits.WaitUntilVisible(ReconciledBalanceValue);
        return balance.Text;
    }

    public int CountStatementLines()
    {
        this.waits.WaitUntilVisible(StatementLineRow);
        IReadOnlyCollection<IWebElement> rows = this.driver.FindElements(StatementLineRow);
        return rows.Count;
    }

    private IWebElement FindStatementLineRow(string transactionReference)
    {
        this.waits.WaitUntilVisible(StatementLineRow);
        IReadOnlyCollection<IWebElement> rows = this.driver.FindElements(StatementLineRow);

        foreach (IWebElement row in rows)
        {
            if (row.Text.Contains(transactionReference))
            {
                return row;
            }
        }

        throw new NoSuchElementException(
            "No statement line row contains transaction reference " + transactionReference + ".");
    }
}
```

| Do | Never |
| --- | --- |
| Expose intent-level methods (`ImportStatement`, `MatchLine`) | Expose `Click` wrappers named after the control |
| Hold named test id `const`s plus `private static readonly By` fields | Cache an `IWebElement` in a field — it goes stale; a `By` does not |
| Wait through the injected `ElementWaits` before every interaction | `Thread.Sleep`, a polling `while` loop, or `catch (StaleElementReferenceException)` |
| Return the next page object when the screen changes | Return `bool` from an immediate `Displayed` check |
| Return a value (`string`, `decimal`, `int`, a record) for the step to assert on | Assert anything |
| Receive `IWebDriver` and `ElementWaits` by constructor injection | Create its own driver |
| Keep methods around 20 lines, three parameters maximum | Build a generic base-class hierarchy — one level of `BasePage` at most |

Methods are plain synchronous methods. No `async`, no `Task`, no `*Async` suffix, no `.Result`.

## Step 5 — Extract reusable fragments into components

A region that appears on several screens — a period selector, an entity picker, a paged grid — becomes a `*Component.cs` in `Components/`, scoped to its own root element so it cannot reach across the page.

```csharp
// src/QAAutomation.UI/Components/PeriodSelectorComponent.cs
public sealed class PeriodSelectorComponent
{
    private const string RootTestId = "period-selector";
    private const string OptionTestId = "period-selector-option";

    private static readonly By Root = TestIdLocator.ByTestId(RootTestId);
    private static readonly By Option = TestIdLocator.ByTestId(OptionTestId);

    private readonly IWebDriver driver;
    private readonly ElementWaits waits;

    public PeriodSelectorComponent(IWebDriver driver, ElementWaits waits)
    {
        this.driver = driver;
        this.waits = waits;
    }

    public void SelectPeriod(string periodLabel)
    {
        IWebElement root = this.waits.WaitUntilClickable(Root);
        root.Click();

        // Re-find the root after the click: opening the dropdown re-renders it.
        IWebElement openedRoot = this.waits.WaitUntilVisible(Root);
        IReadOnlyCollection<IWebElement> options = openedRoot.FindElements(Option);

        foreach (IWebElement option in options)
        {
            if (option.Text == periodLabel)
            {
                option.Click();
                return;
            }
        }

        throw new NoSuchElementException("Period selector has no option labelled " + periodLabel + ".");
    }
}
```

The page object exposes the component as a property or a method; the step never constructs it.

## Step 6 — Waiting: the shared helper, every time

Selenium acts immediately and throws if the element is not ready. There is no auto-waiting to lean on, so the wait is the page object's job and it is explicit on every dynamic interaction.

| Need | Do this | Not this |
| --- | --- | --- |
| Element must exist and be visible before acting | `this.waits.WaitUntilVisible(locator)` | `this.driver.FindElement(locator)` |
| Element must be enabled before clicking | `this.waits.WaitUntilClickable(locator)` | find, then click and hope |
| Text must settle | `this.waits.WaitUntilTextIs(locator, expected)` | read, sleep, read again |
| Spinner must clear | `this.waits.WaitUntilGone(spinner)` | `Thread.Sleep(2000)` |
| Row count must settle | wait for a row to be visible, then `FindElements(...).Count` | `FindElements` straight away and assert on an empty list |
| A new condition the helper does not cover | add **one** method to `ElementWaits` with its own `Until` lambda | write an `Until` lambda inline in the page object |
| Server-side work finished and the UI shows nothing | wait on the UI's own completion signal; if there genuinely is none, settle via the API from a step | inflate the global timeout |

Rules worth repeating because they are the ones that get broken:

1. **One `Until` lambda per condition, in one file.** `WebDriverWait.Until` is the lambda exception in #[[file:code-style.md]]; it is not a licence to scatter lambdas through page objects.
2. **Leave the implicit wait at zero.** Mixing implicit and explicit waits makes timeouts unpredictable and the resulting flakiness is miserable to diagnose.
3. The timeout lives in a `*Options` class under `Configuration/`, set once, raised only with evidence.
4. `ElementWaits` already ignores `NoSuchElementException` and `StaleElementReferenceException` inside its `Until`, so the retry is bounded and lives in one place. A `try`/`catch` in a page object is a review failure.

Assertions stay in the step, on what the page object returned:

```csharp
// Selenium is synchronous, so the step is a plain void method.
[Then("the reconciled balance is {decimal}")]
public void ThenTheReconciledBalanceIs(decimal expectedBalance)
{
    string actualBalance = this.bankReconciliationPage.ReadReconciledBalance();
    string expectedText = expectedBalance.ToString("N2", CultureInfo.GetCultureInfo("en-GB"));

    actualBalance.Should().Be(expectedText,
        because: "the reconciled balance shown to the user must match the matched-transaction total");
}
```

Note that `ReadReconciledBalance` waits internally, so the step is not racing the UI. That is the whole point of putting the wait in the page object: a step can never forget one.

## Step 7 — Handle the generated-markup and stale-element risks explicitly

| Risk | Mitigation |
| --- | --- |
| Auto `id` / hashed `class` changes on upgrade | never locate on them; the `data-testid` contract is the whole answer, and Selenium has no fallback |
| A control is regenerated without its test id | the id is emitted by the template, so the fix is one template change, not one per screen |
| Row order or DOM nesting changes | match rows by business content with a `foreach`; scope to a component root |
| A whole region is regenerated with new structure | one page object owns that region, so the blast radius is one file |
| Field appears or disappears from a generated form | assert the field, do not assume it; contract drift is a finding, not a flake |
| **Vue re-renders between find and act** (`StaleElementReferenceException`) | hold the `By`, resolve at the point of use, wait for the container to settle first, re-find rather than retry — never `catch` it |
| **Element found but not yet interactive** | `WaitUntilClickable`, not `WaitUntilVisible`, before a click |

When a structural selector is genuinely unavoidable, it carries a comment with the reason and a work-item link, and it is replaced when the id lands. An unexplained XPath is a review failure.

## Step 8 — Review gate

| # | Check |
| --- | --- |
| 1 | File is `*Page.cs` in `Pages/` or `*Component.cs` in `Components/`; namespace mirrors the folder. |
| 2 | Class is `sealed`; one level of inheritance at most. |
| 3 | Every locator is priority 1 or 2, or priority 3 with a justification comment and a ticket. |
| 4 | Test ids are named `const` fields; locators are `private static readonly By` built through `TestIdLocator`. |
| 5 | Methods are intent-named, **synchronous**, around 20 lines, three parameters maximum. No `*Async` suffix. |
| 6 | Navigation methods return the next page object, passing the driver and the waits through. |
| 7 | No assertion anywhere in the file; a value is returned for the step. |
| 8 | Every interaction with a dynamic element goes through `ElementWaits`. No bare `FindElement` on anything the app renders asynchronously. |
| 9 | No `Thread.Sleep`, `Task.Delay`, polling loop, `Displayed`-as-assertion, or `catch (StaleElementReferenceException)`. |
| 10 | No `IWebElement` cached in a field; no `static IWebDriver`; the page object does not create its own driver. |
| 11 | No new `Until` lambda in the page object — new conditions go into `ElementWaits`. |
| 12 | No LINQ outside the three exceptions; explicit types; `foreach` for row matching; no null-conditional chains. |
| 13 | No credentials, tenant names or customer-shaped data; placeholders are `YOUR_API_KEY_HERE`. |
| 14 | Screen names, field names and lifecycle states are marked **(ASSUMPTION)** where unconfirmed. |
